# 多卡实验矩阵

本文说明如何在当前仓库中使用 **8 卡并发实验矩阵**，
一次性并行跑多个建模思路，并自动汇总评估结果。

## 1. 设计目标

当前仓库的主模型 `S1Predictor` 规模较小，
更适合：

- 每张 GPU 跑一个独立变体
- 并行比较 baseline / ablation / primary 思路
- 训练完成后自动生成 compare 图与 summary 表

当前入口不是 DDP，
而是 **多 GPU 并发实验调度器**：

`matrix yaml -> generated train yamls -> per-GPU train/eval -> summary/compare`

入口模块：

- `python -m uwnav_dynamics.cli.train_matrix`

代码位置：

- `src/uwnav_dynamics/cli/train_matrix.py`

## 2. 配置文件

样例配置：

- `configs/launch/pooltest02_s1_8gpu_compare.yaml`

顶层结构如下：

```yaml
base_train_yaml: configs/train/pooltest02_s1_lstm_v0.yaml

launcher:
  work_dir: out/train_matrix/pooltest02_s1_8gpu
  gpus: [0,1,2,3,4,5,6,7]
  max_parallel: 8
  run_eval: true
  eval_split: test
  compare: true

common_overrides:
  run:
    device: cuda
    amp: true
  data:
    batch_size: 512
    num_workers: 4
    pin_memory: true
  train:
    epochs: 120

runs:
  - name: b0_seed0
    label: B0 baseline seed0
    role: baseline
    overrides:
      run:
        seed: 0
        variant: B0_baseline_seed0
```

说明：

- `base_train_yaml`
  - 作为所有变体的共同起点
- `launcher.gpus`
  - 指定可用 GPU 列表
- `launcher.work_dir`
  - 保存日志、summary、compare 图
- generated train yaml
  - 固定落在 `configs/train/generated/<work_dir_name>/`
- `common_overrides`
  - 对所有变体统一生效
- `runs[*].overrides`
  - 只对当前变体生效
- `runs[*].role`
  - 可选：`primary / baseline / ablation`
  - compare plot 会用它决定视觉层级

## 3. 启动命令

在仓库根目录：

```bash
cd /home/wys/uwnav_dynamics
source ~/venvs/uwnav_dynamics/bin/activate
export PYTHONPATH=src
```

启动 8 卡实验矩阵：

```bash
python -m uwnav_dynamics.cli.train_matrix \
  -c configs/launch/pooltest02_s1_8gpu_compare.yaml
```

若要在后台运行：

```bash
nohup bash -lc 'cd /home/wys/uwnav_dynamics && source ~/venvs/uwnav_dynamics/bin/activate && export PYTHONPATH=src && python -m uwnav_dynamics.cli.train_matrix -c configs/launch/pooltest02_s1_8gpu_compare.yaml' > train_matrix.log 2>&1 &
```

## 4. 输出目录

以样例配置为例，主要产物位于：

```text
out/train_matrix/pooltest02_s1_8gpu/
```

其中通常包含：

- `logs/*.log`
- `manifest.yaml`
- `summary.csv`
- `compare_test/*.png|pdf`

物化后的训练配置固定保存在：

```text
configs/train/generated/<work_dir_name>/*.yaml
```

训练与评估正式产物仍按原仓库契约落在：

```text
run.out_dir / run.variant
```

例如：

```text
out/ckpts/pooltest02_s1_8gpu/B1_thruster_seed0/
```

该目录下仍会有：

- `best.pth`
- `last.pth`
- `resolved_train.yaml`
- `split_indices.npz`
- `scalers/`
- `eval_test/metrics.yaml`

## 5. 如何看结果

主比较入口不是训练日志，而是：

- `summary.csv`
- `compare_test/rmse_model_compare_horizon.*`
- `compare_test/mae_model_compare_horizon.*`
- `compare_test/control_readiness_compare.*`
- `compare_test/control_readiness_compare_masked.*`

`summary.csv` 会汇总每个变体的：

- `rmse_global`
- `mae_global`
- `rmse_global_masked`
- `mae_global_masked`

建议先看：

1. `summary.csv` 的全局指标排序
2. compare 图里的 `Vel` 组 horizon 曲线
3. `control_readiness_compare.*` 里的末步误差 / 增长率 / 尾部误差 / 偏差
4. 各 run 自己的 `eval_test/metrics.yaml`

## 6. 当前建议的 8 卡矩阵

样例配置默认跑以下 8 组：

- `B0 baseline seed0`
- `B0 baseline seed1`
- `B0 hidden512`
- `B0 hidden512 layers3`
- `B1 thruster`
- `B2 hydro`
- `U1 uncertainty`
- `B4 thruster+hydro`

这样做的目的不是一次性找到“最终论文最优解”，
而是先快速判断：

- 提升来自更大 backbone，还是来自物理先验 blocks
- 哪些思路在 masked velocity 指标上真正有收益
- 哪些改动只是训练更慢，但没有稳定提升
