# 建模路线图

## 1. 当前建模边界

当前模型是一个控制导向、短时多步、数据驱动的动力学近似器。

它当前建模的是：

- 推进器命令到未来短时状态响应的映射
- 多频异步传感器融合后的主时间轴监督
- 通过 blocks 注入有限的物理先验

它暂不直接建模：

- 完整 6-DOF 连续时间闭式动力学
- 显式流体参数辨识
- 闭环控制器中的优化器与约束逻辑

## 2. 状态变量定义

当前工程中的监督目标可理解为：

- `Acc 3`
- `Gyro 3`
- `Vel_state 3`

它是一个工程上可训练、与控制近邻相关的状态代理，而不是最终论文层面的“唯一标准状态定义”。

## 3. 观测变量定义

当前主要观测与输入角色如下：

- PWM：控制输入
- IMU：高频主观测
- DVL：低频速度观测，天然稀疏
- Power：低频辅助特征

当前实现更接近“观测驱动的状态代理预测”，而不是“从纯物理状态方程出发的可观测系统辨识”。

## 4. 稀疏监督问题

DVL 的关键挑战是：

- 采样低频
- 只覆盖部分目标语义
- 若被错误密集化，会在训练中制造伪标签

因此未来建模路线应继续沿以下方向推进：

- 显式 mask-aware loss
- 稀疏 velocity 目标与 dense IMU 目标的联合建模
- 区分“缺失”与“数值很小”

## 5. 物理先验 blocks

当前 blocks 提供的是“弱结构先验”，不是完整物理模型：

- `ThrusterLag`
- `HydroSSM`
- `DampingHead`
- `UncertaintyHead`

未来建模重点不是继续堆模块，而是回答两个问题：

- 哪些先验真正提升 rollout 稳定性与可解释性
- 哪些先验在控制闭环里带来可验证收益

## 6. 不确定度建模

当前项目保留异方差输出头，是因为水下多源观测天然存在：

- 传感器噪声变化
- DVL 掉测
- 运动工况变化
- 未建模流体扰动

后续需要继续推进：

- 不确定度校准评估
- NLL 与控制风险接口的关系
- 稀疏监督下的不确定度解释

## 7. 未来控制接口

未来控制接口的核心问题不是“模型能不能预测”，而是：

- rollout 在小范围闭环中是否稳定
- 不确定度能否用于约束收紧或风险敏感控制
- 模型接口能否被 MPC / 规划器消费

因此控制建模路线建议为：

1. 先把短时 rollout 语义做稳定
2. 再把 mask-aware 监督做正确
3. 最后再与控制代价函数和约束接口对接
