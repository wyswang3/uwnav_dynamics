# 绘图风格规范

## 1. 文档目标

本文档用于统一 `uwnav_dynamics` 的图像输出风格，使其同时适用于：

- 日常数据 QA
- 工程调试汇报
- 论文与技术报告插图

设计原则：

- 克制
- 一致
- 可复现
- 便于论文化

## 2. 适用范围

当前主要覆盖两类图：

- 预处理与传感器诊断图
- 训练后评估图与 rollout 图

若未来新增控制仿真图，也应继承同一视觉语言。

## 3. 字体与排版

推荐规则：

- 字体风格统一，不同图类不混用完全不同字族
- 轴标签、刻度、图例字号保持固定层级
- 图中不堆长标题，详细解释交给 caption 或文档正文

建议默认：

- 正文字体：serif 风格
- 轴标签：清晰、含单位
- 图例：简洁，避免重复解释

## 4. 图尺寸

建议预设两类尺寸：

- 单栏图：适合论文正文单列
- 宽图：适合对比图与多子图布局

同一批实验输出应尽量使用同一尺寸模板，避免视觉比例漂移。

## 5. 坐标轴规则

统一要求：

- 所有轴标签必须包含物理量与单位
- 时间轴命名保持一致
- 子图共享轴时只保留必要的重复标签
- 网格线轻量，不压过主体曲线

## 6. 图例规则

图例应满足：

- 只解释必要语义
- 避免把注释写成图例
- 多子图中尽量减少重复图例

## 7. 颜色与语义映射

建议采用稳定语义映射，而不是每次脚本自动随机选择：

- 输入 / 控制相关曲线使用一组颜色语义
- 观测 / 真值使用一组颜色语义
- 预测 / rollout 使用另一组颜色语义
- 误差带或不确定度区间使用低饱和度填充

## 8. 导出格式

推荐同时支持：

- `png`：快速浏览与开发日志
- `pdf`：论文与正式报告

命名应稳定，至少包含：

- 图类别
- 数据集或 run 标识
- split 或样本编号

## 9. 当前工程建议

当前最重要的不是“做复杂视觉设计”，而是保证：

- 同一评估批次的 horizon 图风格一致
- rollout 样例图可直接进入技术报告
- 预处理图不被调试风格污染

## 10. 与代码的关系

当前绘图实现主要位于：

- `src/uwnav_dynamics/viz/eval/`
- `src/uwnav_dynamics/viz/plots/`
- `src/uwnav_dynamics/viz/style/`

当代码与本文档不一致时，应优先同步二者，而不是长期容忍风格漂移。
